# Playwright Test Cases SPEC Format

Use this Markdown format as the contract between `abd-ops-ui-testcase-refiner` and `abd-qa-playwright-generator`.

```md
# Playwright Test Cases SPEC

## Metadata

- Source document:
- Source repo:
- Generated at:
- Generated by:
- Product/app:
- Environment assumptions:

## Test Case Index

| TC ID | Title | Type | Role | Route/Endpoint | Mutation Risk | Automation Readiness |
| --- | --- | --- | --- | --- | --- | --- |
| TC-UI-OPS-EXAMPLE-001 | Example title | workflow | admin user | /example | yes | ready |

## Test Cases

### TC-UI-OPS-EXAMPLE-001 - Example title

Source requirement:
- Link, section title, or pasted requirement reference.

Type:
- smoke | functional | workflow | API E2E

Role:
- Example: admin user

Routes:
- /login
- /transactions/new

Endpoints:
- POST /v1/transaction

Preconditions:
- User can log in.
- Required account/data exists.

Test Data:
- username:
- source account:
- destination account:
- network:
- amount:

UI Operation Steps:
1. Navigate to ...
2. Click ...
3. Fill ...

API Operation Steps:
1. Send request ...
2. Capture response field ...

Expected Assertions:
- Assert ...
- Assert ...

Recommended Locators:
| UI element | Recommended locator | Stability | Source |
| --- | --- | --- | --- |
| Sign In button | getByRole('button', { name: 'Sign In' }) | stable | Login component |

Page Object Suggestions:
- LoginPage.login(...)
- TransactionPage.selectNetwork(...)

API Client Suggestions:
- TransactionApiClient.submitTransaction(...)
- TransactionApiClient.waitForTransactionStatus(...)

Async/Wait Rules:
- Wait for ...
- Poll until ...

Mutation Risk:
- none | creates data | approves data | deletes data | updates backend state

Automation Readiness:
- ready | needs-live-verification | blocked

Data-testid Recommendations:
- component-action-name

Open Questions:
- ...
```

Guidance:

- TC IDs must be stable and preserved once created.
- Use `TC-UI-...` for browser/UI tests.
- Use `TC-API-...` only for API/backend tests.
- Keep operation steps concrete enough that a QA repo can generate Playwright without reading product source.
- Separate selection labels from later verification labels if the UI displays different names on different pages.
